# Support Engine — project explorer

Open `project-explorer.html` in a browser. This self-contained file needs no build or server. `dist/index.html` is the editable multi-file version. The architecture uses native SVG, so it does not depend on Mermaid rendering or external diagram services.

The explorer includes a selectable system map, three request simulations, a searchable 21-concept library with Obsidian deep links, and six expandable build milestones. Everything shown is proposed architecture or illustrative behavior; no enterprise services, models, or payments are called.

Browser review marks use local storage and do not update Obsidian notes. The app does not read any personal vault content. Only the project-specific seed notes and design are included in the downloadable notebook.

Source is the buildless HTML, CSS, and JavaScript in `dist/`. The shared concept content is generated by `python3 knowledge-base/build.py` from the repository root. Obsidian setup and safe manual updates are documented in `../knowledge-base/README.md`.

After editing the source, run `python3 visualization/build_html.py` from the repository root to refresh the standalone HTML and portable zip.

Verified in local headless Chrome: component selection, all three simulations, approval/rejection, concept search and reset, Obsidian link targets, browser review persistence, roadmap sections, and mobile page overflow. Simulations do not test the future backend implementation.

The map shows both Redis roles: RQ scheduling and Pub/Sub notices. Each simulated worker step commits before publishing. The stream replays PostgreSQL history after reconnect. The diagrams do not imply that Pub/Sub notices are durable.

The system flowchart uses a vertical main path with horizontal calls to PostgreSQL, the model API, and mock APIs. Three stages separate request acceptance, worker execution, and live progress. Numbered arrows show commit before enqueue and commit before publish. Repeated boxes refer to the same component. Redis supplies both RQ and Pub/Sub in one deployment. Select a box for details below the chart.
